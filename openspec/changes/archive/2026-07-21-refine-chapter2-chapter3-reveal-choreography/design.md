## Context

`115MoneyDemoB-main/index-v2.html`'s `updateChapter2Stage()` toggles `.rebuilt-step-1`...`.rebuilt-step-9` on `#chapter-2-rebuilt`; today `.rebuilt-step-1` has zero CSS selectors gated on it (nothing chart-related renders on card 1), and every `.rebuilt-step-2` selector (panel frame, grid, Y-axis, X-axis) fires together on card 2. `updateChapter3Bars()` toggles `.ch3-step-1`/`.ch3-step-2` on `#chapter-3-rebuilt`; `#ch3-bar-total-grey` shares the generic `.ch3-single-bar-layer` transition (opacity 0.4s, width 0.8s) with every other bar — red, dark-grey, etc. — with no distinct treatment. Chapter 3 already computes `--ch3-exit-offset` (distance from `#ch3-card-five-trigger` to the viewport) and applies it as a `translateY` on `#ch3-sticky-box-wrapper`, but never touches the last card's own opacity, unlike Chapter 2's `updateHistoryExit()` (extended in `fix-responsive-story-acceptance-gaps` to also fade `finalStoryCard`). `#ch3-sticky-box-wrapper` is `position: sticky; top: var(--chart-stage-top)` — deliberately anchored below the fixed header per the archived `chart-viewport-clearance` spec. Chapter 3's `.chapter-intro` is a plain static block with no JS gating; it only reads as "waiting for Chapter 2 to clear" because Chapter 2's fixed stage (`#gantt-stage-rebuilt`) stays `position: fixed` and visually on top until `stage-active-rebuilt-now` is removed, which only happens once Chapter 2's entire section has scrolled past.

## Goals / Non-Goals

**Goals:**

- Give Chapter 2 card 1 a distinct "empty/gray" chart state, separate from card 2's axis-highlight state.
- Give `#ch3-bar-total-grey` a reveal treatment distinguishable from the other bar layers.
- Verify Chapter 3's last card and chart already move together during exit (they do, structurally, via the existing sticky+transform mechanism — see decision below) and make that guarantee explicit in spec.
- Make the Chapter 3 sticky box's content read as vertically centered within the space the fixed header already leaves available, without reopening the header-clearance problem `chart-viewport-clearance` was written to prevent.
- Make Chapter 3's intro-reveal timing an explicit, testable class/transition instead of an incidental side effect of the fixed-stage lifecycle.

**Non-Goals:**

- No changes to Chapter 1 (tracked separately in `refine-chapter1-timeline-choreography`).
- No literal full-viewport centering of `#ch3-sticky-box-wrapper` that moves its top anchor away from `--chart-stage-top` — that would let the fixed header overlap the chart on short viewports, undoing the already-shipped `chart-viewport-clearance` guarantee.
- No change to Chapter 2's own step-9 exit guard (already correct after `fix-responsive-story-acceptance-gaps`) — Chapter 3's own mechanism is structurally different (see decision below) and does not need that same fix ported.

## Decisions

### Chapter 2 card 1: add a gray/empty frame state gated on `.rebuilt-step-1`, deferring axis opacity to `.rebuilt-step-2` unchanged

Two options: (a) show the full grid+axes on card 1 too, just dimmed; (b) show only the panel frame and grid (muted gray, no axis emphasis) on card 1 via a new `.rebuilt-step-1` selector on `ganttBox`/`.gantt-grid-rebuilt`, leaving the existing `.rebuilt-step-2`-gated Y-axis/X-axis opacity rules exactly as they are so axis highlighting still only appears on card 2.

**Chosen: (b).** This is the minimal change that satisfies the request — it adds one new low-opacity/gray-toned rule for card 1 without touching card 2's existing (already-correct) axis-reveal timing, avoiding any risk of the two states blurring together.

### `#ch3-bar-total-grey`: an explicit reveal rule with its own duration/easing, not a shared one

Two options: (a) leave grey on the same shared `.ch3-single-bar-layer` transition and just reorder when its visibility class is applied; (b) add a grey-specific transition (distinct duration/easing, e.g. a touch slower or with a slight delay) on `#ch3-bar-total-grey` directly, overriding the shared rule for this one layer.

**Chosen: (b).** A shared transition value can't visually distinguish "the grey base layer establishing itself" from "a colored bar growing" — an override on the specific ID is the only way to make the grey layer read as its own distinct beat before the colored bars appear on top of it.

### Chapter 3 last card/chart "scroll up together": already satisfied by the existing sticky+transform mechanism — verify, don't reimplement

Two options: (a) port Chapter 2's `updateHistoryExit()` opacity-fade pattern to Chapter 3's last card, treating this as a code gap parallel to Chapter 2's; (b) recognize that Chapter 3's mechanism is structurally different and already correct: `updateChapter3Bars()` already computes `--ch3-exit-offset` (`min(wrapperHeight, max(0, containerTop - cardFiveTop))`) every frame and applies it as `translateY(-exitOffset)` on `#ch3-sticky-box-wrapper` — the sticky chart box physically moves in lockstep with the last card's position, recalculated fresh from live geometry each frame and capped at the wrapper's own height. Chapter 2 needed an opacity fade because its backdrop is `position: fixed` and never moves on its own; Chapter 3's chart is `position: sticky` and already moves via this transform, so there is no overlap to guard against with a second, independent fade.

**Chosen: (b).** Adding a redundant opacity fade on top of an already-correct movement-based guard would be the same "two independently-computed things that can drift apart" failure pattern `fix-responsive-story-acceptance-gaps` closed elsewhere — not a fix. This item is verification-only: confirm the existing mechanism holds at the target viewports, and add a spec requirement documenting the already-correct behavior (previously unspecified, not previously incorrect) so a future edit can't silently regress it without a spec check catching it.

### `#ch3-sticky-box-wrapper` vertical centering: override the actual cascade winner (`align-items: flex-start !important` at line ~3024), desktop-only, keep the top anchor

Two options: (a) change `top: var(--chart-stage-top)` to `top: 50%` + `translateY(-50%)`, centering the box in the full viewport regardless of header height; (b) keep `top: var(--chart-stage-top)` and `height: var(--chart-stage-height)` exactly as they are (preserving the header-clearance guarantee), and add a desktop-scoped override for the rule that is *actually* winning today.

Tracing the real cascade (not just the first-declared rule) matters here: `.gantt-sticky-box-rebuilt` is declared `align-items: center` at its base rule and again inside the ≤1024px block, but a later **unconditional** (not media-scoped) rule sets `align-items: flex-start !important` — equal specificity, equal `!important` weight, later in source order, so it wins at every breakpoint today, not just desktop. The box's content is genuinely top-anchored everywhere right now. Centering it back is safe because the same unconditional rule's own `padding: calc(var(--chart-stage-content-clearance) + 16px) 0 var(--chart-stage-gap)` already enforces the top/bottom clearance minimums `chart-viewport-clearance` requires — `align-items` only redistributes slack *within* the padded content box in flexbox, it cannot shrink the padding itself. In the worst case (content exactly fills the padded box) centering and flex-start render identically; in every other case centering only adds more clearance above/below than the enforced minimum, never less.

**Chosen: (b), scoped to `@media (min-width: 1025px)` only** (this bucket is desktop-scoped unless noted), via a rule with equal-or-higher specificity placed after line ~3024's rule so it wins the cascade at that tier while leaving intermediate/compact's existing `flex-start` untouched. Because the fix is provably compatible with `chart-viewport-clearance`'s normative clearance minimums (padding, not alignment, enforces them), no MODIFIED requirement is needed on that spec — only an ADDED clarifying scenario stating that vertical distribution of slack within the cleared region is a presentation choice the spec's clearance requirements don't constrain.

### Chapter 3 intro reveal: reuse the already-computed `history-exit-complete` state, not a coarser stage-lifecycle signal

Two options: (a) toggle the intro's reveal class on `stage-active-rebuilt-now` being removed from Chapter 2's fixed stage (only true once Chapter 2's entire `getBoundingClientRect()` has scrolled past — a coarse, late signal); (b) reuse `history-exit-complete`, a class `updateHistoryExit()` **already toggles** on `#gantt-stage-rebuilt` the instant its computed exit `progress` reaches 1 — i.e., the exact moment the last card/backdrop fade has actually finished, which happens well before the chapter's literal DOM bottom scrolls past.

**Chosen: (b).** `stage-active-rebuilt-now`'s removal is a much later, coarser signal than the actual fade completion, which would leave a stretch of scrolling through already-faded content before the intro appears — the opposite of "waits until the fade is done, then appears." `history-exit-complete` ties the intro's reveal to the exact state it should depend on (same principle as every other decision in this and the prior Bucket-1 change), and requires no new geometry computation since `updateHistoryExit()` already sets it every frame.

## Implementation Contract

- **Behavior**: (1) Chapter 2 card 1 shows a muted gray chart frame+grid with no axis emphasis; card 2 adds the axis highlight exactly as it already does today (unchanged timing); (2) `#ch3-bar-total-grey` visibly establishes itself with its own transition before/independently of the colored bars' shared transition; (3) Chapter 3's last card and chart already move together during exit via the existing `--ch3-exit-offset` transform — no behavior change, verify and document; (4) at `≥1025px`, `#ch3-sticky-box-wrapper` keeps `top: var(--chart-stage-top)` unchanged, and its content visibly centers within `--chart-stage-height` instead of the currently-winning top-anchored (`flex-start`) alignment; (5) Chapter 3's `.chapter-intro` fades in via an explicit class toggled from the already-existing `history-exit-complete` state on `#gantt-stage-rebuilt`.
- **Interface/data shape**: no new JS globals. Item 4's fix is CSS-only (one new desktop-scoped `align-items` override). Item 5 adds one new class (e.g. `.chapter3-intro-revealed`) read from the existing `history-exit-complete` class inside `updateChapter2Stage()`, which already has `stage` in scope. Items 1 and 2 are CSS-only additions to `.rebuilt-step-1`/`#ch3-bar-total-grey`. Item 3 requires no code change.
- **Failure modes**: none beyond existing — all additions are presentational and derived from values already computed every frame; no new async/event-driven failure surface (unlike Bucket 1's `transitionend`-based sequencing) is introduced here.
- **Acceptance criteria**: at desktop width, Chapter 2 card 1 visibly differs from card 2 (gray frame vs. highlighted axes); `#ch3-bar-total-grey` visibly precedes/differs from colored bars' reveal; forward-and-reverse scrolling through Chapter 3's ending shows the sticky chart box and the last card visually staying together with no overlap (existing behavior, confirmed not regressed); at `≥1025px`, `#ch3-sticky-box-wrapper`'s content visibly centers within the header-safe band while its top offset stays `var(--chart-stage-top)`, verified at 1366x768 and 1440x900 with the `96年度` label still ≥24px below the header; at `<1025px`, alignment is unchanged (still top-anchored); Chapter 3's intro fade-in begins exactly when `history-exit-complete` is added to `#gantt-stage-rebuilt`, not later.
- **Scope boundaries**: in scope — `#chapter-2-rebuilt`'s step-1/step-2 CSS, `#ch3-bar-total-grey`'s CSS, `#ch3-sticky-box-wrapper`'s desktop-scoped `align-items`, and Chapter 3's `.chapter-intro` CSS/JS, all within `115MoneyDemoB-main/index-v2.html`. Out of scope — Chapter 1, any change to `--chart-stage-top`/`--chart-stage-height`/the padding values that enforce clearance, any change to Chapter 2's already-shipped step-9 exit guard, any change to `updateChapter3Bars()`'s existing `--ch3-exit-offset` computation itself.

## Risks / Trade-offs

- [Treating item 7 as verification-only assumes the existing `--ch3-exit-offset` cap (`min(wrapperHeight, ...)`) is sufficient at every supported viewport height] → Mitigation: the acceptance-criteria viewport pass explicitly checks forward/reverse/fast-scroll-jump behavior at 1366x768 and 1024x768-ish laptop heights before this item is considered closed; if that pass finds a real gap, it becomes a follow-up task rather than being silently assumed away.
- [A grey-specific transition override could visually clash if a future redesign changes the shared bar-layer transition without updating the grey override to match] → Mitigation: keep the override minimal (duration/easing only, not a structurally different animation) so future shared-transition edits are unlikely to look inconsistent even if not also applied to grey.
- [Overriding `align-items` at `≥1025px` relies on the padding-enforces-the-minimum argument holding for all supported chart content, not just today's content] → Mitigation: the acceptance criteria explicitly re-check the `96年度`-label clearance scenario (the exact case `chart-viewport-clearance`'s short-laptop requirement was written for) at 1366x768/1440x900, so any future content change that grows the chart tall enough to defeat the padding minimum would be caught by that same check.
